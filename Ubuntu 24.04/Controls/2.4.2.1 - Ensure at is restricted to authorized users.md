# 35601 - Ensure at is restricted to authorized users  

**Profilo CIS:** CIS Ubuntu Linux 24.04 LTS Benchmark for Level 1 - Server
**Versione:** 1.0.0 (2024)
**Riferimento Compliance:** ISO 27001:2013 A.9.1.1 | CIS-2.4.2.1
**Data del fix:** 26 Maggio 2026
**Stato:** Pass

## Requisito del Controllo
L’utility `at` deve essere accessibile **solo agli utenti autorizzati**. Su un server di produzione l’unico utente autorizzato deve essere `root`. L’uso di `/etc/at.allow` (allow-list) è la modalità preferita e più sicura rispetto a `/etc/at.deny`.


## Fix Applicato
- Installato il pacchetto `at`
- Creato `/etc/at.allow` contenente solo `root`
- Impostati permessi restrittivi (600)
- Rimossa `/etc/at.deny` (se presente)

**Comandi eseguiti:**
```bash
# Installazione del pacchetto at
sudo apt install at -y

# Crea /etc/at.allow con solo root
echo "root" | sudo tee /etc/at.allow

# Permessi restrittivi
sudo chmod 600 /etc/at.allow

# Rimuove at.deny (non serve più con at.allow presente)
sudo rm -f /etc/at.deny
```

## Motivazione
Solo l’amministratore di sistema deve poter pianificare job con `at`. Utilizzare un file `at.allow` rende la gestione più semplice e sicura: è più facile mantenere una lista bianca che una nera, evitando di dimenticare utenti che potrebbero essere aggiunti al sistema

## Verifica
```bash
# Verifiche CIS richieste
dpkg-query -s at | grep Status                     # → install ok installed

stat -Lc "%U %G" /etc/at.allow                     # → root root (o root daemon)
stat -Lc "%a" /etc/at.allow                        # → 600
ls -l /etc/at.allow                                # verifica file esistente

# Controllo che at.deny non esista più
ls -l /etc/at.deny 2>/dev/null || echo "at.deny rimosso correttamente"
```

**Output atteso:**
- `at` installato
- `/etc/at.allow` → owned by `root:root`, permessi `600`
- `/etc/at.deny` non esiste
