# 35632 - Ensure nftables rules are permanent

**Profilo:** CIS Ubuntu Linux 24.04 LTS Benchmark – Level 1 Server  
**Riferimento Compliance:** ISO 27001:2013 A.13.1.1 | CIS-4.3.10
**Versione:** 1.0.0 (2024)  
**Stato:** Pass  (Compliant - False Positive su Wazuh SCA)
**Data del fix:** 28 Maggio 2026

## Requisito del Controllo
Le regole nftables devono essere configurate in modo da essere **caricate automaticamente all’avvio** del sistema.  
Il file `/etc/nftables.conf` deve contenere almeno una direttiva `include` che carica il ruleset persistente.

## Fix Applicato
- Salvato il ruleset corrente (input/output/forward + tutte le catene personalizzate BRUTE, set allowed_ips, denylist, ecc.) nel file `/etc/nftables.rules`
- Ricreato `/etc/nftables.conf` con struttura standard (`#!/usr/sbin/nft -f` + `flush ruleset` + `include`)
- Abilitato e avviato il servizio `nftables`

**File configurati:**
- `/etc/nftables.conf`
- `/etc/nftables.rules`

**Comandi eseguiti:**
```bash
sudo nft list ruleset | sudo tee /etc/nftables.rules
cat <<EOF | sudo tee /etc/nftables.conf
#!/usr/sbin/nft -f
flush ruleset
include "/etc/nftables.rules"
EOF
sudo systemctl enable --now nftables
```

## Motivazione
Le modifiche fatte solo in memoria (`nft` comandi) vengono perse al riavvio.  
La configurazione tramite `/etc/nftables.conf` garantisce che tutto il firewall (default drop, protezioni brute-force, allowed_ips, ecc.) venga ricaricato automaticamente al boot, soddisfacendo pienamente il requisito di persistenza CIS 4.3.10.

## Verifica 
```bash
# Controllo che soddisfa Wazuh
grep -E 'include' /etc/nftables.conf

# Verifica ruleset caricato
sudo nft list ruleset | grep -E 'chain (input|output|forward)'

# Verifica servizio
systemctl is-enabled nftables && systemctl is-active nftables
```

**Output atteso:**
```
include "/etc/nftables.rules"
chain input { type filter hook input priority filter; policy drop; ...
chain output { type filter hook output priority filter; policy drop; ...
chain forward { type filter hook forward priority filter; policy drop; ...
enabled
active
```
