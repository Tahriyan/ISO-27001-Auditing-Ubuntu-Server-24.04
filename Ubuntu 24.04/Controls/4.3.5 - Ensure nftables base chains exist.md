# 35629 - Ensure nftables base chains exist

**Profilo:** CIS Ubuntu Linux 24.04 LTS Benchmark – Level 1 Server  
**Riferimento Compliance:** ISO 27001:2013 A.13.1.1 | CIS-4.3.5 
**Versione:** 1.0.0 (2024)  
**Stato:** Pass (Compliant - False Positive su Wazuh SCA)  
**Data del fix:** 28 Maggio 2026

## Requisito del Controllo
Devono esistere tre **base chains** di tipo filter con hook per `input`, `forward` e `output` nella tabella `inet filter`.  
Queste catene rappresentano i punti di ingresso obbligatori per il traffico di rete in nftables.

## Fix Applicato
**Nessun intervento necessario.**  
Le tre base chains (`input`, `forward`, `output`) sono già presenti e correttamente configurate con:
- `type filter`
- hook corretto per ogni direzione
- `priority filter` (sintassi moderna Ubuntu 24.04)
- `policy drop` su tutte e tre

**Configurazione attuale:**
- `/etc/nftables.conf` (o equivalente) già contiene le catene base con policy deny di default.

## Motivazione
Le base chains sono il requisito fondamentale per far sì che nftables processi tutto il traffico di rete.  
La configurazione presente soddisfa pienamente lo spirito della raccomandazione CIS 4.3.5 e garantisce una **default deny policy** su input/forward/output, riducendo drasticamente la superficie di attacco.

Il fallimento del controllo Wazuh è dovuto esclusivamente a regex obsoleti che non riconoscono la sintassi `priority filter;` introdotta nelle versioni recenti di nftables.

## Verifica 
```bash
# Verifica diretta delle base chains (output attuale)
sudo nft list ruleset | grep -E 'chain (input|forward|output)'

# Verifica completa (deve mostrare tutte e tre le catene)
sudo nft list ruleset | grep -E 'type filter hook (input|forward|output) priority filter'
```
