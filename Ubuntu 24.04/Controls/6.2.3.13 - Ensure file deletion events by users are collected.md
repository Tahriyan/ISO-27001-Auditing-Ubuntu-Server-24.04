# 35742 - Ensure file deletion events by users are collected

**Profilo:** CIS Ubuntu Linux 24.04 LTS Benchmark – Level 1 Server  
**Riferimento Compliance:** CIS 6.2.3.13 | ISO 27001:2013 A.12.4.1 | CIS-6.2.3.13
**Versione:** 1.0.0 (2024)  
**Stato:** Pass  
**Data del fix:** 28 Maggio 2026  

## Requisito del Controllo
Monitorare le operazioni di cancellazione o rinomina di file (`unlink`, `unlinkat`, `rename`, `renameat`) eseguite da utenti non privilegiati. Questo rileva potenziali tentativi di rimuovere tracce o file protetti da parte di un attaccante.

## Fix Applicato
Sostituito il file di regola con la versione **pulita** (senza backslash `\` sulle righe spezzate) per evitare errori di parsing in `augenrules`.

**File configurati:**  
`/etc/audit/rules.d/50-delete.rules`

**Comandi eseguiti:**

```bash
sudo tee /etc/audit/rules.d/50-delete.rules << 'EOF'
-a always,exit -F arch=b64 -S unlink,unlinkat,rename,renameat -F auid>=1000 -F auid!=unset -k delete
-a always,exit -F arch=b32 -S unlink,unlinkat,rename,renameat -F auid>=1000 -F auid!=unset -k delete
EOF

# Carica le regole e riavvia auditd
sudo augenrules --load
sudo systemctl restart auditd
```

## Motivazione
Le cancellazioni o rinominazioni di file da parte di utenti normali possono indicare attività malevole (cancellazione di log, rimozione di prove, ecc.). Il tag `delete` permette di filtrare facilmente questi eventi nei log di audit.

## Verifica

```bash
# Verifica regole attive
sudo auditctl -l | grep -E 'delete'

# Verifica file di regola
cat /etc/audit/rules.d/50-delete.rules
```
