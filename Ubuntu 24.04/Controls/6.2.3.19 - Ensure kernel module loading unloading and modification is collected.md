# 35748 - Ensure kernel module loading unloading and modification is collected
**Profilo:** CIS Ubuntu Linux 24.04 LTS Benchmark – Level 1 Server  
**Riferimento Compliance:** CIS 6.2.3.19 | ISO 27001:2013 A.12.4.1
**Versione:** 1.0.0 (2024)  
**Stato:** Pass  (Compliant - False Positive with Wazuh SCA)
**Data del fix:** 28 Maggio 2026  

## Requisito del Controllo
Monitorare il caricamento, lo scaricamento e la modifica dei kernel module (`init_module`, `finit_module`, `delete_module`, ecc.) e l’uso del comando `kmod`. Questo rileva tentativi di inserire rootkit o modificare il kernel a runtime.

## Fix Applicato
Ricreato il file di regola **pulito** (senza backslash `\` sulle righe spezzate) per evitare che `augenrules` fallisca di nuovo.

**File configurati:**  
`/etc/audit/rules.d/50-kernel_modules.rules`

**Comandi eseguiti:**

```bash
sudo tee /etc/audit/rules.d/50-kernel_modules.rules << 'EOF'
-a always,exit -F arch=b64 -S init_module,finit_module,delete_module,create_module,query_module -F auid!=unset -k kernel_modules
-a always,exit -F path=/usr/bin/kmod -F perm=x -F auid!=unset -k kernel_modules
EOF

# Carica le regole e riavvia auditd
sudo augenrules --load
sudo systemctl restart auditd
```

## Motivazione
I kernel module sono uno dei vettori più pericolosi per rootkit e persistenza. Monitorare ogni caricamento/scaricamento/modifica garantisce che qualsiasi tentativo di alterare il kernel sia immediatamente visibile nei log di audit.

## Verifica

```bash
# Verifica regole attive
sudo auditctl -l | grep -E 'kernel_modules'

# Verifica file di regola
cat /etc/audit/rules.d/50-kernel_modules.rules
```

**Output atteso:**
