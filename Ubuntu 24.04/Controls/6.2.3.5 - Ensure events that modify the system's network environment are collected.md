# 35735 - Ensure events that modify the system's network environment are collected
**Profilo:** CIS Ubuntu Linux 24.04 LTS Benchmark – Level 1 Server  
**Riferimento Compliance:** CIS 6.2.3.5 | ISO 27001:2013 A.12.1.2 | CIS-6.2.3.5
**Versione:** 1.0.0 (2024)  
**Stato:** Pass  
**Data del fix:** 28 Maggio 2026  

## Requisito del Controllo
Monitorare tutte le modifiche all’ambiente di rete del sistema (hostname, domain name, file di pre-login, host mapping, configurazioni di rete e Netplan). Questo permette di rilevare tentativi di alterazione dell’identità di rete o di reindirizzamento malevolo.

## Fix Applicato
Aggiornato il file di regola esistente aggiungendo il monitoraggio mancante su `/etc/netplan/` (era l’unico motivo per cui il controllo risultava **Failed**).

**File configurati:**  
`/etc/audit/rules.d/50-system-locale.rules`

**Comandi eseguiti:**

```bash
sudo tee /etc/audit/rules.d/50-system-locale.rules << 'EOF'
-a always,exit -F arch=b64 -S sethostname,setdomainname -k system-locale
-a always,exit -F arch=b32 -S sethostname,setdomainname -k system-locale
-w /etc/issue -p wa -k system-locale
-w /etc/issue.net -p wa -k system-locale
-w /etc/hosts -p wa -k system-locale
-w /etc/networks -p wa -k system-locale
-w /etc/network/ -p wa -k system-locale
-w /etc/netplan/ -p wa -k system-locale
EOF

# Carica le regole e riavvia auditd
sudo augenrules --load
sudo systemctl restart auditd
```

## Motivazione
Le modifiche a hostname, domain name o ai file di configurazione di rete possono essere usate da un attaccante per deviare traffico, nascondere la propria presenza o preparare ulteriori attacchi. Il tag `system-locale` permette di correlare facilmente questi eventi.

## Verifica

```bash
# Verifica regole attive
sudo auditctl -l | grep -E 'system-locale'

# Verifica file di regola
cat /etc/audit/rules.d/50-system-locale.rules
```
