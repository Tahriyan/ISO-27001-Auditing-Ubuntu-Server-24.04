# 35736 - Ensure unsuccessful file access attempts are collected
**Profilo:** CIS Ubuntu Linux 24.04 LTS Benchmark – Level 1 Server  
**Riferimento Compliance:** CIS 6.2.3.7 | ISO 27001:2013 A.12.4.3 | CIS-6.2.3.7
**Versione:** 1.0.0 (2024)  
**Stato:** Pass  
**Data del fix:** 28 Maggio 2026  

## Requisito del Controllo
Monitorare tutti i tentativi falliti di accesso ai file (EACCES ed EPERM) da parte di utenti non privilegiati. Questo rileva tentativi di accesso non autorizzato o probe di privilege escalation.

## Fix Applicato 
Sostituito il file di regola con la versione **pulita** (senza backslash `\` alla fine delle righe).  
Questo evita che `augenrules` generi errori nel file `/etc/audit/audit.rules` (come succedeva prima).

**File configurati:**  
`/etc/audit/rules.d/50-access.rules`

**Comandi eseguiti:**

```bash
sudo tee /etc/audit/rules.d/50-access.rules << 'EOF'
-a always,exit -F arch=b64 -S creat,open,openat,truncate,ftruncate -F exit=-EACCES -F auid>=1000 -F auid!=unset -k access
-a always,exit -F arch=b64 -S creat,open,openat,truncate,ftruncate -F exit=-EPERM -F auid>=1000 -F auid!=unset -k access
-a always,exit -F arch=b32 -S creat,open,openat,truncate,ftruncate -F exit=-EACCES -F auid>=1000 -F auid!=unset -k access
-a always,exit -F arch=b32 -S creat,open,openat,truncate,ftruncate -F exit=-EPERM -F auid>=1000 -F auid!=unset -k access
EOF

# Carica le regole e riavvia auditd
sudo augenrules --load
sudo systemctl restart auditd
```

## Motivazione
I tentativi falliti di apertura/creazione/truncatura di file da parte di utenti normali sono un forte indicatore di attività malevole (scanning, brute-force su permessi, ecc.). Il tag `access` permette di filtrare facilmente questi eventi.

## Verifica

```bash
# Verifica regole attive
sudo auditctl -l | grep -E 'access'

# Verifica file di regola
cat /etc/audit/rules.d/50-access.rules
```
